# 算法说明

[English](ALGORITHM.md)

## 1. 扰动

对 `z_{n+1} = z_n² + c`，取参考点 `c0` 并以全精度算出轨道 `Z_n`；像素写成
`c = c0 + d0`、`z_n = Z_n + d_n`：

```
曼德勃罗集：d_{n+1} = 2 Z_n d_n + d_n² + d0
朱丽叶集：  d_{n+1} = 2 Z_n d_n + d_n²          （无常数项）
```

Julia 少一个 `+d0` 是整帧画错的高频原因：那里 `c` 固定，`d0` 只是**初值**，
不是递推常数项。`RefCache::julia` 同时切换标量、AVX2 四宽、double-double 三套
内核与 distance 导数；级数系数也必须按同一语义积分，否则 SA 帧整帧错
（1e12 处曾差 179/255 像素）。

逐像素用 float-exp（double 尾数 + int64 指数），1e-60000 的偏移也不下溢；
1e-250 以上指数不会溢出，走纯 double 快路径。AVX2 的 `iterate_quad_d`
每步处理四个像素，与标量逐字节相同，由 `#if defined(__AVX2__)` 保护。

## 2. 参考轨道铁律（B2–B10 实测）

1. **参考必须比所有像素活得久**：帧内 24×16 探针反复提升长寿候选。
2. **`ref_cap = maxiter` 一步给满**：Example 14 真逃逸在 28026…39815 步，
   8192 上限会把整帧判成 interior。轨道一逃逸就停，×4 阶梯只是重算前缀。
3. **并行 8 条候选**（互相散开），`build_best()` 留最长寿者。
4. **glitch 判据 `|Z+d| << max(|Z|,|d|)`**（丢 20 bit，即 `2^-20`）。抵消会
   毁掉扰动递推，该像素改用局部参考修复。float-exp 加法必须**全量归一化**
   指数域（`f2_norm` 按位重写），只归一化尾数不够。
5. **级数近似**：设 `d_n = A_n d0 + B_n d0² + C_n d0³ + …`，截断项必须相对
   **首项**可忽略：
   ```
   log10|A_N| - log10|A_1| + (N-1)·log10(dmax) < -12
   ```
   `|Z| > 2` 必须封口（`SaTracker::step`），否则 skip 会落到逃逸点之后。
   系数只依赖已存的 `z_n`，于是 `sa_replay()` 事后重放：所有轨道以 `sa=0`
   建立，阶梯末尾重放一次。预览 order 8、整帧 16。配对保护
   （`ref.rdx==rdx && ref.rdy==rdy`）防止未被采纳的候选覆盖当选参考。
6. **精确最终周期**：头 64 步用 `__gmpf_cmp` 精确比较，位级重复即说明轨道
   解析周期，随后把 `orbit.z` 平铺到 `maxiter`，零次额外全精度平方。
   **锚点必须是精确视点中心**（`*p->cr/ci`）：中心像素是
   `center + 0.5px·scale`，并不是 Misiurewicz 点。`RefCache::anchor_x/y`
   （double，`w/2-0.5`）驱动所有 `d0`，配对保护仍用整数 `rdx/rdy`。
   `c=i` 从 `z_2` 起周期 2。`MB_QUASI=1` 放宽到 CFexp（53 位）判据但
   **默认关闭**：`c=i+1e-6050` 只是看似周期，冻结 `Z_n` 是错的。
7. **Julia 递推** —— 见第 1 节。
8. **坐标按本帧位宽解析**：`BigFloat::from_string` 用 `thread_local`
   limb 数；浅帧残留 90 位会把 1e100 的 180 位中心截掉 90 位，结构轻微漂移。
   宿主必须**先**按 `log10_zoom+80` 设 `precision_limbs`，再解析坐标。
9. **迭代预算来自观测**：`canvas->maxiter` 是已观测最大实际迭代数，顶点预算
   `known*3+3000`。"饿死"帧 `cap>0 && hi===0 && refLen>=cap-1` 直接跳到
   80000 并**自动重渲一趟**（`observedIter.repainted`，`refine≤3`），否则
   用户永远看到被截断的黑块。

## 3. 周期中心与深坐标

- `mset misiurewicz --m M --p P`：Newton 解 `z_{m+p}(c)-z_m(c)=0`。
  `(2,2) → c=i`，`(3,1) → c=-2`。小于 `10^-(digits-6)` 的分量清零
  （否则 `c=i` 会输出 92 位噪声）。任意核也是 `g=0` 的解，Newton 可能收敛回核。
- `mset nucleus`：原子域测周期 + Newton 解 `z_p(c)=0`。Example 14 →
  周期 11196（200 位 0.2 s，6100 位 21 s）。以核为中心放大必然全
  interior，这是数学正确，不是故障。
- 超长坐标走 `--config view.json`（Windows 命令行上限 8191 字符）。

## 4. 精度

- `digits = depth10 + 50`，按 64 bit limb 对齐，上限 1.2 Mbit。
- 参考轨道用运行时加载的 GMP `mpf`（`gmp_bridge.cpp`），`__mpf_struct` 当
  32 字节不透明块，绝不读字段；自研 10^9 进制 BigFloat 是回退。
- `BigFloat::to_floatexp` 必须补足 17 位有效数字（原来只读两个 limb ⇒ 10 位），
  修后 GMP / BigFloat 轨道差 ≤4.4e-16。
- **核心禁止 `std::exp2` / `std::pow` / `std::exp`**：该 exe 配对的 CRT/libm
  对它们返回垃圾，改用 `pow10_int`、`fexp_pow2_frac`、`fexp_exp`。
  这一个故障曾两次造成整帧纯色。
- 像素尺度唯一定义 `mbc::pixelScaleLog2`，必须 inline 在 `mb_core.h`。

## 5. 验证与耗时

oracle：BigFloat 精确核 88 位与 268 位一致，`cmp` 逐像素比较。
1e6 为 98.71%，1e20 / 1e38 为 100%，0 unresolved；Julia
1e6/1e12/1e20/1e38 对 `--exact` 均 0 像素差。

| 视点 | 耗时 |
| --- | --- |
| 1e38，426×240 | 44 ms |
| 1e73，640×400 | 475 ms |
| 1e6000 `c=i`，320×200 | 84 ms |
| 1e60000 `c=i`，160×100 / 200000 迭代 | 0.65 s |
| 200×120 / 2000 迭代：1e600 / 1e2000 / 1e6000 / 1e20000 | 52 / 98 / 272 / 1050 ms |

AVX2 四宽内核把主趟从 33 ms 降到 8 ms；深帧几乎全耗在参考轨道而非像素上。
GMP 在 6000/12000/24000/60000/120000 位每步 22/43/106/463/980 µs，
**没有 FFT 阈值跳变**，所以换 FFT 乘法不是优化方向。1e60000 的墙是
**全精度步数**，不是乘法算法。

## 6. 已实测否定（别再查）

- 缩放抖动不是双精度抵消，而是预览/成帧切换与量化网格；锚点漂移是 CDP
  整数坐标假象。
- 整帧缓存更慢且并发写越界；按 64px 瓦片建局部参考在 1e38 需 243 条轨道。
- "到 1e78 极限" = `ref_cap` 截断；"1e6000 平坦" = 坐标位数不够；
  "需要 FFT 乘法" = 错。
- "小亮环正常"、"导出黑是视点在集合内部" 均作废（那是 exp2 故障）。
