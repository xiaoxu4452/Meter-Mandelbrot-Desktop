Mandelbrot View 0.9  ·  深视点分形引擎
=====================================================================

这个目录是从 C:\Users\harve\Desktop\mande\new 构建出来的完整产品。
两个程序共用一个渲染核心（src\deep.cpp + src\reference.cpp）。

  Mandelbrot View.exe   桌面程序（Win32 + WebView2，界面即工作台）
  mset.exe              命令行引擎（可脚本化、可验证、可批处理）
  libgmp-10.dll         高精度参考轨道运行库，必须与 exe 同目录

---------------------------------------------------------------------
怎么用
---------------------------------------------------------------------
桌面：双击 Mandelbrot View.exe。滚轮定点缩放，拖动平移，360ms 静默后出整帧。

命令行：
  mset.exe info
  mset.exe render --center-re -0.743643887037151 --center-im 0.13182590420533 \
                  --zoom 1e12 --width 1200 --height 800 --maxiter 4000 --out deep.png
  mset.exe nucleus --center-re X --center-im Y --digits 300
                   Newton 缩放：原子域检测周期，解 z_p(c)=0 求小曼德博集核
  mset.exe misiurewicz --m 2 --p 2 --digits 300
                   解 z_{m+p}(c)-z_m(c)=0 求 Misiurewicz 点 (0+1i 是 m=2,p=2)
  mset.exe --help        全部参数

长坐标（> 4000 位）走 JSON：mset.exe render --config view.json --out deep.png

A/B 开关（只影响性能，不改画面，用于自检）：
  MB_GMP=0       强制回退到自研 BigFloat 轨道
  MB_PERIOD=0    关闭周期轨道解析复用
  MB_QUASI=1     允许"准周期"检测（见已知限制）
  MB_CENTER_REF=0  参考锚点用中心像素而非精确中心
  B2_SIMD=0      强制标量像素核
  B2_SA_REPLAY=0 恢复旧的"重建一条带级数系数的轨道"
  B2_REFCAP=N    固定参考轨道步数上限
  B2_TIME=1      打印每趟耗时、每条轨道耗时、glitch 分布

---------------------------------------------------------------------
它是什么
---------------------------------------------------------------------
· 参考轨道 + 归一化扰动 + 级数近似，逐像素算术用 floatexp（double 尾数 + 整数指数），
  像素偏移小到 1e-60000 也不下溢；1e-250 以上自动走纯 double 快路径。
· 参考轨道用 GMP 的 mpf（运行时加载 libgmp-10.dll，不链接、不内置），位宽 =
  缩放位数 + 50 位保护位。DLL 缺失时自动回退到自研 10^9 进制 BigFloat。
· 轨道一次建到 maxiter，级数系数在已存的 z_n 序列上事后重放：一帧只需一条
  高精度轨道。帧内探针并行建最多 8 条候选参考、留活得最久的那条。
· 像素核 AVX2 四像素并行，与标量路径逐字节相同。
· **最终周期轨道解析复用**：Misiurewicz 点的临界轨道从某一步起精确重复（c=i
  从 z_2 起周期 2）。在头 64 步用 mpf_cmp 检出精确重复后，后续 z_n 直接按
  周期平铺，不再做全精度平方。这是 10^60000 从"几十分钟"变成"不到一秒"的原因。
· `mset nucleus` / `mset misiurewicz` 是深坐标生成器：把中心算到任意位数。
  官方示例最深只到 1.54e73（98 位坐标），再深必须有对应的坐标位数。

---------------------------------------------------------------------
已验证
---------------------------------------------------------------------
· 轨道级：gmporbit 在 80/120/250/500/900 位逐元素对比 GMP 与 BigFloat，最大差
  4.4e-16（一个 double ulp）；sareplay 对比循环内积分与事后重放，逐位相同。
· 精度：cmp 用全精度逐像素判据，1e6 98.71% / 1e20 100% / 1e38 100%，
  0 unresolved。1e20/1e38 的满分来自精确中心锚点（修掉半个像素的参考偏移）。
· 输出一致性：GMP 与 BigFloat、SIMD 与标量、replay 开与关、周期复用开与关，
  PNG 全部逐字节相同。
· Julia 集：1e6/1e12/1e20/1e38 与 --exact 逐像素一致（此前 1e12 整帧错 179/255）。
· 1e100 坐标完整性：parsewidth 自检证明旧的解析顺序会丢 90 位低位数字，
  修复后 180 位全保留（这就是"放大到 10^100 结构轻微改变"的原因）。
· 10^60000：c=i、160x100、maxiter 200000 = 0.65 s，esc 159453..159488，
  有自相似丝状边界；参考轨道只花 40.7 ms。

耗时（本机，非并发测量）
  1e38   426x240   maxiter 3000       44 ms
  1e73   640x400   maxiter 40000      475 ms
  1e6000 c=i 320x200  maxiter 30000   84 ms   （此前 4.10 s）
  1e60000 c=i 160x100 maxiter 200000  0.65 s  （此前 20 分钟不出帧）

---------------------------------------------------------------------
关于"FFT 级乘法"
---------------------------------------------------------------------
实测 gmpbench（6000..120000 位十进制，每步 2 次大数乘）：

  digits    6000    12000    24000    60000    120000
  us/step   21.9    43.2     106      463      980

倍率 ~2.0 / 2.5 / 4.4 / 2.1，没有出现 FFT 阈值那种斜率突降；GMP 6.3 在
200k bit 仍用 Toom-Cook，因为在这个规模它比 FFT 更快（阈值是按实测最优设的）。
所以瓶颈不是"没换乘法算法"，而是 160000 步 × O(n^1.46) 的总量。
正确的杠杆是**减少必须做全精度乘法的步数**：周期轨道解析复用做到了这一点，
而且输出与全精度轨道逐字节相同。真要再往更深的一般（非周期）视点推进，
需要 MPIR / FLINT 一类阈值更低的后端，或自写 NTT，且收益在 200k bit 上未必为正。

---------------------------------------------------------------------
已知限制
---------------------------------------------------------------------
· 周期复用只对**精确可知**的 Misiurewicz 坐标自动生效（c=i、c=-2 等）。Newton
  求出的坐标带有数值残差，mpf 逐位比较不会判定为周期，仍需全精度轨道。
  MB_QUASI=1 放宽到 CFexp（53 位尾数）判据可加速这类坐标，但**默认关闭**：
  c=i+1e-6050 只是"看起来"周期，真实轨道会发散，冻结 z_n 会得到错误结果。
  只有在中心确实来自 `mset misiurewicz`、残差是 c 的数值噪声时才应开启。
· 所有像素都在集合内部的视点仍要跑满 maxiter，这是算法本性。
· 从 1e73 自动递归到 1e6000 的逐级 Newton dive 尚未实现：核邻域网格扫描
  只返回同一周期。当前可用的深坐标来源 = nucleus / misiurewicz / 精确 Misiurewicz 点。
· 直接以核为中心放大必然全 interior（数学正确）；要看结构需把中心放在核附近
  的小曼德博集边界，或用 c=i 这类 Misiurewicz 点。
· 浅视点（zoom < 1e8）用 double 直接迭代，混沌区边界像素与 BigFloat oracle
  可能有 ±1 次迭代差异，这是精度取舍而非错误。

怎么重建
---------------------------------------------------------------------
核心源码 C:\Users\harve\Desktop\mande\new\src，两条命令出全套：
  buildall.bat      -> build\mset.exe
  buildapp.bat      -> 编桌面程序并导出到 dist\（本目录）
  buildapp.bat --no-build    只导出，不重编
  b2.bat cmp / gmporbit / sareplay / parsewidth / gmpbench    自检

gmp_bridge.cpp 与 dive.cpp 必须同时出现在 buildall.bat、b2.bat、桌面 build.bat
三处源列表里。buildall.bat 必须带 /arch:AVX2，否则 SIMD 段会被整段编译掉。
本机 cmake 不可用（安全策略拦 reg.exe），构建脚本直接调 cl；bat 保持纯 ASCII。
